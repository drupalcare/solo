# Solo changelog

## Next release

- Extend and Appearance pages: every module and theme description is a short, professional statement that begins with a verb; credits, links and version notes moved out of the info files.

**Sub-theme owners: this release renames Solo's CSS classes and element IDs, so your sub-theme's CSS, Twig and JavaScript break until you migrate them.** Run `drush solo:migrate-classes my_theme` first. It is a dry run and changes nothing. Read the list, then run it again with `--apply`. `drush updatedb` also rewrites the inline CSS saved in Solo's settings.

- A new site starts with the social icons off and no social links filled in (they used to point to the maintainer's accounts). The footer credit link stays. Existing sites keep what they saved.
- Region border colors: in Berry Blue Dreams, Cotton Candy Whispers and Monochrome Splash, a region's own border color now reaches the content inside the region. Four leftover scheme rules re-declared the scheme's border color on every element inside the main or top container, which blocked it.
- Every Solo class and ID now starts with `solo-` and follows one naming pattern. The full list of old and new names is in `docs/CLASS-MIGRATION.md`.
- The starter sub-theme (`solo_subtheme`) uses the new names.
- Accessibility: the color-coded system tabs (View, Edit, Delete, Revisions) use darker fills, so the white label on hover and on the active tab reads at 4.5:1 or more. The label at rest keeps the region link color instead of a light green or blue that failed 4.5:1.
- Text follows the drupal.org standards: the theme description begins with a verb and no longer opens links in new windows, setting labels say "content" instead of "node" and "YouTube" instead of "Youtube", the preloader reads "Loading…", and the README follows the drupal.org README template.
- Mega menu: the script that moves dropdowns away from the screen edge no longer touches mega menu panels, which lay out their own columns.
- Accessibility: a skip link (header, main navigation, main content, footer) shows only when its region has content, so it never jumps to a target that is not on the page.
- `solo_subtheme` is now a Drupal core starterkit (`solo_subtheme.starterkit.yml`, `src/StarterKit.php`), so `php core/scripts/drupal generate-theme my_theme --starterkit solo_subtheme --path themes/custom` works. `drush solo:subtheme` is unchanged for users.
- Solo and Solo Utilities work without the Search module, which Drupal 12 core no longer ships. The Search Results settings show a short note asking you to install Search, and the saved search settings are kept.
- `solo.libraries.yml` now holds only `solo-global` and `solo-menu`. Solo Utilities builds every other library (fonts, color schemes, breakpoints, components, w3-css) from the data files in `fonts/`, `schemes/`, `scripts/breakpoints/` and `libraries/`. Library names and their files are unchanged, so `libraries-override` and `libraries-extend` in a sub-theme keep working.
- JavaScript follows Drupal core's ESLint and Prettier rules. As in core's own JavaScript, files no longer start with `'use strict';`.
- Spelling: a project word file and an ignore list for vendored fonts, W3.CSS and translations let the spell-check job pass; comments and docs use American English.
- CSS follows Drupal core's Stylelint and Prettier rules, and the CI job now lints Solo's own `css/` folder. Media queries use `min-width`/`max-width` (core's rule). Only formatting, property order and notation changed; computed values are the same.
- Breakpoint build: the 1200px upper bound of the tablet layouts now comes from `scripts/breakpoints/breakpoints.json` through a `{{MAX_1200}}` placeholder in `scripts/build-breakpoints.py`. The generated CSS is unchanged.
- Accessibility: hover-only menus are reachable by keyboard (Enter or Space opens the dropdown); the search panel always moves focus into its field and back to its opener; social icons have text names and say when they open a new tab; the login opener keeps its visible label as its name; the preloader is hidden when JavaScript is off; the forced-colors mode shows the animated site name and page title as plain text.
- Footer and copyright bands no longer double their padding: vertical padding is now 24-32px (it was twice the page gap), and the byline on a full node page sits left under the title instead of on the right.
- Accessibility: the footer regions, footer menu and copyright band sit in one `<footer>` landmark (`#solo-footer-landmark`); the copyright band is now a `<div>` inside it, and the footer prints nothing when it is empty.
- Accessibility: the menu branding logo name is the site's own logo alt text as written; only the fallback "Home" is translated.
- Accessibility: the logo and the site name are one link (or, in the header branding block, the logo link is hidden from keyboard and screen readers when the name is printed); the repeated `title` attributes are gone.
- Drupal's admin toolbar (the Navigation module) now sits above Solo's header and menu, so its open menus are no longer covered by Solo's menu bar. Solo sets core's `--drupal-admin-z-index*` variables (sidebar 1201); the old `#admin-toolbar` rule, which core's selector always overrode, is removed. Dialogs use core's level (1260), above the toolbar.
- Midnight Whispers (the default color scheme) lists every region once with its full color set: background, body text, headings and links. Backgrounds are unchanged. Text that missed WCAG AA now passes: link hover in the dark breadcrumb, bottom, footer, footer menu and copyright areas (#c91000 to the scheme's own #a2d3fa); headings in the main and welcome areas (#6c738c to #60677f), top-region headings (#676e86 to #555b72) and top-region link hover (#c91000 to #bc0000) are darker as well. The scheme record gains a description and its five brand colors.
- The other 49 color schemes get the same per-region layout: the old scattered per-region text patches are replaced by one block per region (heading, link, link hover) at the end of each file, with every background and border rule unchanged. 34 text colors in 16 schemes that missed WCAG AA now pass. Most are a shade darker; link hover in dark footer, bottom, breadcrumb and copyright areas now uses the scheme's own light hover color (Shared hover rules used to outrank it). Cotton Candy Whispers' links and page title on its pink header and title bands become near-white.
- Every scheme record (schemes/*.yml) has a short description and its brand colors (menu bar, button, link, menu text, page text). The scheme contrast check now reads each region's own heading color, so all 50 schemes pass it with no known failures left.
- Accessibility: links, buttons and form fields show one two-color focus ring (the region's text color with a halo in its background color), so keyboard focus is visible on any palette; the back-to-top button uses it too.
