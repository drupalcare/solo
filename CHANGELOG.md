# Solo changelog

## Next release

- Font Awesome: a sub-theme that names the 1.x libraries `solo/font-awesome-4-in`, `-4-ex`, `-5-ex` or `-6-ex` keeps its icons; the old ids are deprecated aliases of `solo/font-awesome-7-in` and `solo/font-awesome-7-ex`.
- Font Awesome from the CDN (settings 2, 3 and 4) loads again: the `solo/font-awesome-7-ex` library was dropped because its integrity and crossorigin attributes were rejected.
- Font file paths under `fonts/font-files/` are internal and changed in 2.0; a sub-theme `@font-face` that points at them should attach the `solo/font-<name>-local` library instead.

- New setting: show the breadcrumb before the page title (Global site settings, next to "Flip the main menu order"). Off by default; the page wrapper gets `solo-page--breadcrumb-flipped` when it is on.
- System messages: the region takes no space when there is no message (the block always prints Drupal's hidden placeholder, so an empty, colored band showed under the header on every page).
- Accessibility: the popup login focus ring uses the region text color (3:1 against its ground); `.w3-tiny` to `.w3-jumbo` font sizes and the clickable image caption are in rem, so text-only zoom resizes them.
- Color schemes with gradient region grounds paint the gradient again on the header, page title, bottom, footer and copyright areas.
- W3.CSS copy modernized like W3CSS Theme's: old-browser rules removed, slide and zoom animations no longer undo `.w3-display-*` centering, `.w3-top`/`.w3-bottom` pinned edge to edge, keyboard access to hover content, reduced motion, and 24 new layout classes, including `w3-flex`, `w3-flex-wrap`, `w3-grid`, `w3-grid-2/3/4`, `w3-grid-auto` and `w3-gap` with the same names and values as W3CSS Theme (`css/w3-css/SOURCE.md`).
- `drush solo:migrate-classes` now also migrates library ids, JavaScript names and region color variables and reports moved files; the full list per kind is `docs/CLASS-MIGRATION.md`, generated by Solo Utilities `scripts/class-list.py`.
- Class and JavaScript names follow the template-owner standard: 42 public classes and ids, 8 behaviors, 12 `once()` ids, the `debug_verbosity` settings key, the `solo-aria-change` event and 8 data attributes are renamed (see the README table). Old public class names stay as second selectors in CSS and JavaScript, old behavior names as aliases, and the old key, event and attributes are still sent or read, until the next major.
- Files renamed to the template-owner standard (stylesheets and scripts moved into layer folders, the five breakpoint families renamed `solo-page-sb-*` and `solo-menu-mn-*`, the W3.CSS palettes moved to `css/utilities/solo-color-*.css`, `solo-file.css` and `solo-file-upload.css` merged into `solo-input-file.css`, the empty `solo-menu-keyboard.css` removed). Library ids are unchanged by this step; a sub-theme that names a Solo file path directly must follow the new path.
- CSS layers: the base and layout styles now sit in the solo.reset, solo.tokens, solo.base, solo.layout and solo.utilities layers (reduced motion in solo.locked); the few rules that must beat unlayered module CSS are in the new solo-host-overrides.css.
- CSS layers: the component styles now sit in the solo.theme layer (reduced motion in solo.locked); component rules that must beat unlayered module CSS moved to solo-host-overrides.css, and the node form, Layout Builder and system admin stylesheets stay outside the layers.
- CSS layers: breakpoint, theme and color scheme styles now sit in the solo.theme and solo.schemes layers (reduced motion in solo.locked); rules that must beat unlayered module CSS stay unlayered, at the end of the same file or in solo-host-overrides.css.
- CSS layers: the W3.CSS copy and the 11 color libraries plus the extended classes now sit in layers; every library color is a variable (--solo-<class> and --solo-<class>-on), the color classes set --r-background, --r-text or --r-border and paint from them, and the !important on them is gone (the show/hide helpers and three inline-style overrides keep it in solo.locked); W3.CSS rules that must beat unlayered module CSS moved to solo-host-overrides.css.
- CSS layers: the 254 font stylesheets now sit in layers (`@font-face` blocks stay as they are); page and heading fonts in solo.base, the `.akronim`-style font classes in solo.utilities without `!important`; headings and generic font classes that must beat unlayered module CSS stay unlayered at the end of the same file; Font Awesome stays unlayered.
- Region color variables: all 15 use one set of `--r-<role>` names, are registered as typed colors (`css/base/solo-region-properties.css`, a value that is not a color is ignored), and a gradient goes in `--r-background-image` while `--r-background` holds only a color. The 1.x short names (`--r-tx`, `--r-bg`, `--r-lk`, and the rest in the README table) stay as read-only aliases in `css/base/solo-region-legacy.css` until the next major release; a rule that sets an old name must be rewritten. Both files are generated from `solo_utilities/config/map/solo-variable-map.yml` by `scripts/build-region-legacy.py`.
- Predefined color schemes: the 50 schemes set `--r-heading`, `--r-link`, `--r-link-hover`, `--r-button-text` and `--r-button-text-hover` on each region directly; the `--r-sc-*` scheme defaults are gone (a read-only alias keeps an old name that a sub-theme prints), and a gradient is in `--r-background-image` while `--r-background` holds the gradient's first color (130 values, 48 files). A site's region colors still win on the same region; a color a site sets on the page wrapper no longer overrides a scheme's per-region link and heading colors.
- Fonts: every font can now load locally, from the same updated files APEX ships, each with its license. Local files carry Latin characters only, so a site in another script should keep loading from Google. Bitter, Cairo, Exo 2 and Work Sans stop at weight 800 when local. Irish Grover now shows Irish Grover; its CSS named a different font.
- Social and interface icons follow the link or text color and its hover. A color set in the social icon settings still wins.
- Font Awesome: the only choices are now Font Awesome 7 locally or from the CDN. Sites on the 5.x or 6.x CDN option use Font Awesome 7 from the CDN. Icons that exist only under Font Awesome 4 names may need renaming.
- Templates: brought in line with Drupal 11 core (no redundant landmark roles, description ids on details, the description-before position and classes in form elements, `view_mode` for term titles).
- Extend and Appearance pages: every module and theme description is a short, professional statement that begins with a verb; credits, links and version notes moved out of the info files.
- New Solo logo: it is the theme's default logo (replace or turn it off in Appearance settings), and it sits at the top of the settings menu, which scrolls under it.

**Sub-theme owners: this release renames Solo's CSS classes and element IDs, so your sub-theme's CSS, Twig and JavaScript break until you migrate them.** Run `drush solo:migrate-classes my_theme` first. It is a dry run and changes nothing. Read the list, then run it again with `--apply`. `drush updatedb` also rewrites the inline CSS saved in Solo's settings.

- A new site starts with the social icons off and no social links filled in (they used to point to the maintainer's accounts). The footer credit link stays. Existing sites keep what they saved.
- Region border colors: in Berry Blue Dreams, Cotton Candy Whispers and Monochrome Splash, a region's own border color now reaches the content inside the region. Four leftover scheme rules re-declared the scheme's border color on every element inside the main or top container, which blocked it.
- Every Solo class and ID now starts with `solo-` and follows one naming pattern. The full list of old and new names is in `docs/CLASS-MIGRATION.md`.
- The starter sub-theme (`solo_subtheme`) uses the new names.
- Accessibility: the color-coded system tabs (View, Edit, Delete, Revisions) use darker fills, so the white label on hover and on the active tab reads at 4.5:1 or more. The label at rest keeps the region link color instead of a light green or blue that failed 4.5:1.
- Text follows the drupal.org standards: the theme description begins with a verb and no longer opens links in new windows, setting labels say "content" instead of "node" and "YouTube" instead of "Youtube", the preloader reads "Loading…", and the README follows the drupal.org README template.
- Mega menu: the script that moves dropdowns away from the screen edge no longer touches mega menu panels, which lay out their own columns.
- Accessibility: a skip link (header, main navigation, main content, footer) shows only when its region has content, so it never jumps to a target that is not on the page.
- `solo_subtheme` is now a Drupal core starterkit (`solo_subtheme.starterkit.yml`, `src/StarterKit.php`), so `php core/scripts/drupal generate-theme my_theme --starterkit solo_subtheme --path themes/custom` works. `drush solo:subtheme` is unchanged for users.
- Solo and Solo Utilities work without the Search module, which Drupal 12 core no longer ships. The Search Results settings show a short note asking you to install Search, and the saved search settings are kept.
- `solo.libraries.yml` now holds only `base-layers`, `bundle-global` and `bundle-menu`. Solo Utilities builds every other library (fonts, color schemes, breakpoints, components, w3-css) from the data files in `fonts/`, `schemes/`, `scripts/breakpoints/` and `libraries/`.
- Library ids are renamed to `<layer>-<name>` (for example `solo/solo-sitemap` is now `solo/component-sitemap`, `solo/solo-berry-blue-dreams` is `solo/scheme-berry-blue-dreams`, `solo/solo-gfex-abel` is `solo/font-abel-external`). Every old id stays until Solo 3.0.0 as a deprecated alias that loads the new library, and Drupal logs a deprecation when it is used. `libraries-override` and `libraries-extend` entries on an old id must switch to the new id. `solo/solo-search` is split into `component-search-block` and `component-search-page`; `solo/w3-css` is split into one library per file and the bundle `bundle-w3-css`. Stored settings (font, scheme and breakpoint names) are unchanged.
- JavaScript follows Drupal core's ESLint and Prettier rules. As in core's own JavaScript, files no longer start with `'use strict';`.
- Spelling: a project word file and an ignore list for vendored fonts, W3.CSS and translations let the spell-check job pass; comments and docs use American English.
- CSS follows Drupal core's Stylelint and Prettier rules, and the CI job now lints Solo's own `css/` folder. Media queries use `min-width`/`max-width` (core's rule). Only formatting, property order and notation changed; computed values are the same.
- Breakpoint build: the 1200px upper bound of the tablet layouts now comes from `scripts/breakpoints/breakpoints.json` through a `{{MAX_1200}}` placeholder in `scripts/build-breakpoints.py`. The generated CSS is unchanged.
- Accessibility: hover-only menus are reachable by keyboard (Enter or Space opens the dropdown); the search panel always moves focus into its field and back to its opener; social icons have text names and say when they open a new tab; the login opener keeps its visible label as its name; the preloader is hidden when JavaScript is off; the forced-colors mode shows the animated site name and page title as plain text.
- Footer and copyright bands no longer double their padding: vertical padding is now 24-32px (it was twice the page gap), and the byline on a full node page sits left under the title instead of on the right.
- Accessibility: the footer regions, footer menu and copyright band sit in one `<footer>` landmark (`#solo-footer-landmark`); the copyright band is now a `<div>` inside it, and the footer prints nothing when it is empty.
- Accessibility: the menu branding logo name is the site's own logo alt text as written; only the fallback "Home" is translated.
- Accessibility: the logo and the site name are one link (or, in the header branding block, the logo link is hidden from keyboard and screen readers when the name is printed); the repeated `title` attributes are gone.
- Drupal's admin toolbar (the Navigation module) now sits above Solo's header and menu, so its open menus are no longer covered by Solo's menu bar. Solo sets core's `--drupal-admin-z-index*` variables (sidebar 1201); the old `#admin-toolbar` rule, which core's selector always overrode, is removed. Dialogs use core's level (1260), above the toolbar.
- Midnight Whispers (the default color scheme) lists every region once with its full color set: background, body text, headings and links. Backgrounds are unchanged. Text that missed WCAG AA now passes: link hover in the dark breadcrumb, bottom, footer, footer menu and copyright areas (#c91000 to the scheme's own #a2d3fa); headings in the main and welcome areas (#6c738c to #60677f), top-region headings (#676e86 to #555b72) and top-region link hover (#c91000 to #bc0000) are darker as well. The scheme record gains a description and its five brand colors.
- The other 49 color schemes get the same per-region layout: the old scattered per-region text patches are replaced by one block per region (heading, link, link hover) at the end of each file, with every background and border rule unchanged. 34 text colors in 16 schemes that missed WCAG AA now pass. Most are a shade darker; link hover in dark footer, bottom, breadcrumb and copyright areas now uses the scheme's own light hover color (Shared hover rules used to outrank it). Cotton Candy Whispers' links and page title on its pink header and title bands become near-white.
- Every scheme record (schemes/*.yml) has a short description and its brand colors (menu bar, button, link, menu text, page text). The scheme contrast check now reads each region's own heading color, so all 50 schemes pass it with no known failures left.
- Accessibility: links, buttons and form fields show one two-color focus ring (the region's text color with a halo in its background color), so keyboard focus is visible on any palette; the back-to-top button uses it too.
- Region color variables: `scripts/check-region-vars.py` fails the CI when a removed 1.x name is used anywhere outside the archive, the README table, the changelog and the docs.
