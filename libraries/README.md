# Solo library data

`solo-components.json` is the single source for the Solo libraries that no convention can derive on its own, read by `solo_utilities` (`SoloLibraryDefinitions`) and by the Python checkers in `scripts/`. `libraries` holds one record per component or feature library (`id`, optional `meta` keys written before the files, `css`, `js`, `dependencies`); a stylesheet written as a bare path takes its category and weight from its directory (`css/base` base -200, `css/layout` layout 200, `css/components` component 0, `css/theme` theme 200, `css/debug` theme with no weight) and an object `{path, category, weight, type, minified, preprocess, attributes}` overrides any of them (`"weight": null` means none). `globs` holds file-pattern rules: a rule without an `id` makes one library per matched file named after its stem, a rule with an `id` makes one library from every match, the `first` paths leading in the order given and the rest sorted. Fonts, Font Awesome (`icons`) and breakpoints live in `fonts/solo-fonts.json` and `scripts/breakpoints/breakpoints.json`; only `solo-global` and `solo-menu` stay written in `solo.libraries.yml`.
